# V3 优缺点文档

## V2 vs V3 对比

| | V2 | V3 |
|---|---|---|
| **架构** | LangGraph 状态图（5节点+1子图） | 同 V2 +2 质量检查节点 +3 路由 |
| **质量检查** | 无 | 交叉校验（LLM）+ 物理验证（纯数学） |
| **错误诊断** | 知道"仿真失败了"，不知道原因 | 知道参数不一致 / 物理量偏差 / 修了几次 |
| **语法检查** | 3 个正则（package / 花括号 / part def） | 同 V2（sysmlpy 升级见 V4） |
| **仿真参数** | stopTime 硬编码 0.01s | 根据物理域自动选（电气 0.01 / 热 1000） |
| **CSV 输出** | 依赖 OMPython，经常找不到 | MAT→CSV 转换，稳定可靠 |
| **修复追溯** | 不知道修了什么 | 每次 repair 记录 errors_before + code 前后对比 |
| **实验指标** | 成功率 | 成功率 + 交叉校验通过率 + 物理偏差 + 修复次数 |
| **Windows 兼容** | GBK 编码可能乱码 | 强制 UTF-8 |

## V3 解决了什么

1. **能发现参数搬运错误** — node2 生成 SysML 时把 R=1000 写成 R=10，交叉校验能拦截
2. **能验证仿真物理正确性** — 不只是"编译通过"，还检查截止频率对不对
3. **能追溯修复过程** — repair_log.json 记录每次 LLM 修复前后的代码变化
4. **仿真参数自动化** — 不再需要手动改 stopTime
5. **CSV 输出可靠** — 从 OMPython MAT 文件读时间序列转 CSV，不再丢数据

## 已考虑到的问题（V3 内解决）

| 问题 | 措施 |
|------|------|
| 物理验证跳过（CSV 不存在） | MAT→CSV 转换，fallback 搜索多个目录 |
| modelica/ 路径错 | 子图所有节点显式回传 run_dir + .resolve() |
| CSV 列选错（参数常量 vs 信号） | 按结尾过滤 .C/.R/.alpha 等参数列，优先 sensor.v |
| 交叉校验误报 | 失败不直接阻断，超过 max_rejects 强制放行 |
| Windows GBK 编码 | sys.stdout.reconfigure(encoding="utf-8") |
| LLM 生成废弃语法 | node3 prompt 加规则禁止 `import Modelica.SIunits` |
| 物理验证 len(data) bug | 从 `len(dict)` 改为 `len(data["data"])` |

## V3 的局限（已知但不在这版解决）

| 局限 | 影响 | 何时解决 |
|------|------|---------|
| 交叉校验只查数值，不查语义结构 | 检查不了 port 类型错误、connect 语义错误 | V4 sysmlpy 语法验证 |
| 物理验证只覆盖 RC 截止频率 | RLC 谐振、运放增益等验证公式硬编码 | V4 expected_physics 配置 |
| 矛盾检测只是 prompt 一句话 | 不做独立 LLM 调用，复杂矛盾检测不到 | V8 RAG |
| 语法检查仍是正则 | package/花括号/part def 三个关键词，深层次语法错误全漏 | V4 sysmlpy |
| 只覆盖 2 个物理域（电气+热） | 液压/电机/流体等无法建模 | V4 扩展到 5 用例 |
| 没有跨 run 学习能力 | 同样的错误每个 run 都重新犯 | V8 RAG 检索历史失败案例 |
| 只有 2 个检查点 | 需求↔SysML 和仿真↔理论，中间大片空白 | V7 LLM-as-Judge |
| 没有 SysML↔Modelica 交叉校验 | C=1e-6 是从哪来的？是算的还是编的？ | V7 |
