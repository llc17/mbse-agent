> 报告人: Dengwen

---

## 一、项目概述

设计并实现了一套基于 LLM 的 MBSE（Model-Based Systems Engineering）自动化闭环系统。输入自然语言需求，系统自动生成 SysML v2 系统模型 → Modelica 仿真代码 → 编译/仿真 → 质量验证 → 总结报告，形成完整的"需求→模型→仿真→验证"闭环。

技术栈: LangGraph (状态图编排) + DeepSeek-V4 (LLM) + OpenModelica (仿真) + sysmlpy (语法验证)

## 三、V4 新增能力

### 3.1 sysmlpy 标准语法验证
- 替换 V3 的 3 条正则检查，使用 OMG 标准解析器 `sysmlpy.loads()`
- 打分制：fatal（打回重生成）/ error（记录不阻断）/ warning（放行）
- 含降级策略：sysmlpy 不可用时自动 fallback 正则

### 3.2 Prompt 升级对齐官方写法
- `import ISQ::*` → `private import ScalarValues::*`
- `attribute :> ISQ::xxx` → `attribute : Real`
- 参考官方 training 示例（02 Part Def / 09 Connections / 10 Ports）

### 3.3 多用例扩展 (3→6)
| 用例 | 领域 | 验证量 |
|------|------|--------|
| RC 低通滤波器 | 电气 | f_c = 1/(2πRC) |
| RC 低通 v2 (159Hz) | 电气 | 同上 |
| 单房间热传导 | 热 | 稳态温度 |
| RLC 串联谐振 | 电气 | 谐振频率 f_0 = 1/(2π√(LC)) |
| 双房间热传导 | 热 | 双房间稳态温度 |
| 运放反相放大器 | 电气 | 闭环增益 G = -Rf/Rin |

### 3.4 物理验证配置化
- `expected_physics.validate_type` 驱动验证策略
- 容差 `tolerance_pct` 按用例独立配置
- 4 种验证策略：RC 截止频率 / 热稳态 / RLC 谐振 / 运放增益

### 3.5 节点3 HITL
- 仿真成功后展示关键数值摘要 + PNG 路径
- 用户选项：确认 / 打回 Modelica 重做 / 打回 SysML 重做
- 独立打回计数器，超限强制继续

### 3.6 Token 追踪
- `llm_client` 全局累计 token 消耗
- 实验结束时自动保存 `token_usage.json`

## 五、技术要点

### 5.1 架构设计
```
START → node1(需求解析) → HITL1
     → node2(SysML生成) → 交叉校验 → HITL2
     → node3_subgraph(Modelica+编译+仿真+自修复) → node3_hitl(仿真确认)
     → 物理验证 → node4(总结报告) → END
```

### 5.2 sysmlpy 发现的语法问题
| 问题 | V3 写法 | V4 写法 |
|------|---------|---------|
| import | `import ISQ::*` | `private import ScalarValues::*` |
| attribute | `:> ISQ::resistance` | `: Real` |
| import (冗余) | `import SI::*` | 删除 |

### 5.3 Modelica 仿真适配
- stopTime 自动适配（电气 0.01s / 热 1000s）
- MAT→CSV 转换（解决 OMPython CSV 丢失问题）
- 多域组件支持（RLC 电感、运放 IdealOpAmp）
- CSV 信号列智能识别（传感器优先、参数常量和地电压自动跳过）
