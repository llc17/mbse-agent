## 检查清单（逐条执行）

1. **参数完整性**: component_type 是否明确？核心物理参数是否全部提取？（如 RC 滤波器的 R/C，热系统的热阻/热容/温度）— 如果缺核心参数，severity=fatal。

2. **参数值合理性**: 参数值是否在工程合理范围内？（如电阻 1Ω~10MΩ，电容 1pF~1F，温度 200K~500K）— 明显不合理 severity=error。

3. **拓扑描述明确性**: topology 是否足够具体？（"串联"太笼统——应该说明谁连谁、顺序如何）— 太笼统 severity=warning。

4. **约束一致性**: 参数之间是否自洽？（如 f_c = 1/(2πRC)，三个值是否数学一致）— 不一致 severity=error。

5. **Boolean 字段禁用**: 不要输出 true/false 以外无法量化的模糊字段（如 is_working: true）— 有 severity=warning。

## 输出格式（严格 JSON）
```json
{
  "ok": true/false,
  "score": 0-100,
  "issues": [
    {
      "severity": "fatal|error|warning",
      "category": "completeness|consistency|semantics",
      "description": "具体问题描述",
      "location": "涉及的字段名",
      "suggestion": "具体修改建议（给出建议值）"
    }
  ],
  "summary": "审查总结（一句话）"
}
```

## 重要规则
1. 只报硬伤（缺核心参数、参数值无物理意义、公式不一致），不挑命名风格
2. 不确定的问题不要写——宁可漏报不要误报
3. 如果所有检查项都通过，ok=true，issues=[]，score>=90
4. engineering fields的不精确描述不算问题（如topology="串联RC"而不指定顺序是可以接受的）
5. 不要输出 JSON 之外的任何内容
